| 权威写法 | 含义 |

## 0. 一句话概括

xasset 是一个 **AI 驱动的 3D 场景生成引擎**，用一套统一的方法论叫 **Artist**：把场景生成拆成六个工作阶段（Stage），每个 Stage 内部都是「LLM（想法）× 边界约束（求解器）」的迭代收敛；每个 Stage 同时是一个**独立产品单元**，可用「插件 / 软件 / 页面」三种产品形态包装，先各自独立成型，再组合成整体服务。

---

## 1. 方法论核心：Artist

**Artist** 取自艺术家创作的类比：

> 艺术家分阶段创作（先轮廓、再主体、最后细节），每一笔都在「大脑的想法」与「现实的约束」之间迭代收敛。

| Artist 概念 | 系统对应 |
|------------|---------|
| 大脑的理解与想法 | **LLM**（语义理解、意图选择） |
| 现实的约束 | **边界约束**（确定性规则 + 求解器） |
| 每一笔的迭代收敛 | Stage 内部「想法 → 求解 → 校验 → 回拉新想法」循环 |
| 一幅完成的作品 | 场景生成（数据结果） |

三个关键性质：

1. **LLM 与边界约束不分工到不同 Stage**——每个 Stage 内部**同时**有这两套机制
2. **迭代收敛**，不是线性「先 LLM 后约束」——LLM 出想法 → 约束求解落地 → 校验门拦截回拉 → 再出新想法，直到该阶段定型
3. **边界约束是确定性的求解器 + 校验门**，不是软约束、不是又一个 LLM——它负责"把想法变成合法现实"

---

## 2. 两轴正交的完整结构

系统有两条**正交的轴**，理解它必须同时看：

### 轴一：实现方式（Stage 内部怎么做）
「LLM × 边界约束」迭代收敛

### 轴二：产品形态（Stage 怎么交付）
插件 / 软件 / 页面，三种宿主包装

> 同一份 Stage 实现，可以**同时**封装成三种产品形态——两轴互不绑定。

---

## 3. 六层 Stage：轮廓 → 主体 → 细节

六层 Stage 顺序重排为「轮廓 → 主体 → 细节」，每个 Stage 都是独立产品单元（独立输入 / 独立输出 / 独立形态）：

| 阶段 | Layer | 工作内容 | 产品形态（示例） |
|------|-------|---------|----------------|
| **轮廓** | `understand` | 语义理解：场景 / 区域 / 类型 | 页面 |
| **轮廓** | `geometry` | 边界 / 骨架：2D → 3D 几何 | 插件 |
| **主体** | `layout` | 主体造型：组合摆放 | 插件 |
| **主体** | `surface` | 表面覆盖：铺贴 | 页面 |
| **细节** | `accessory` | 点缀：小件散布 | 插件 |
| **细节** | `stylize` | 风格化：材质 / 灯光 / 相机 | 页面 |

**Scene Type 矩阵**：每个 Layer 按 `(layer, scene_type)` 分发，house / urban / wild 三场景。当前 house 完整，urban / wild 的 geometry / layout 还是缺口。

---

## 4. Stage 接口（范式化契约）

每个 Stage 通过统一的接口契约对内外交互：

- **`input_type` / `output_type`**：明确的输入输出契约（schema 唯一权威定义在 `schemas/` 层）
- **`run(ctx) -> T`**：返回类型化阶段产物，框架强校验
- **内部持有**：`LLMProvider`（想法侧）+ `solvers`（求解器）+ `constraints`（校验门）

**框架职责收敛到最小**：注入 LLMProvider、顺序执行、output_type 强校验、失败中断——不干预 Stage 内部的迭代细节（那是各 Stage 自己的事）。

---

## 5. 关键概念地图

| 概念 | 定义 |
|------|------|
| **Stage** | 工作阶段（六层，轮廓 / 主体 / 细节） |
| **LLM** | 想法侧：语义理解与意图选择 |
| **边界约束** | 现实侧：确定性规则 + 求解器 + 校验门 |
| **迭代收敛** | 两套机制在 Stage 内反复协作直至定型 |
| **阶段产物** | 每个 Stage 的定型结果（= 输出契约） |
| **轮廓语义** | 区域轮廓上的门 / 窗 / 固定边等（开口 + 固定边） |
| **输入输出契约** | 每个 Stage 输入输出的唯一 schema 定义 |
| **产品形态** | 插件 / 软件 / 页面 三种交付形态 |

---

## 6. 两条贯穿性设计原则

1. **约束校验是强制默认项，没有例外**——任何要呈现给用户或送下游的结果，先过校验门，不因"算法看似可靠"而跳过
2. **速写轮廓 + 自然语言迭代编辑**——不追求单次高精度，先产出"语义正确的大致初稿"，精度缺口由约束校验 + 用户的自然语言编辑闭环收敛

---

## 7. 演进方式：先插件后整体服务

- **引擎**（`xasset/`）：六层 pipeline + LLM 抽象 + 边界约束工具，可 `pip install`，不独立运行
- **产品**（`products/`）：组合引擎模块、独立发布——每个 Stage 先以独立产品成型，再串成整体服务
- **分支**：master / xasset-urban / xasset-outdoor 三分支并行
