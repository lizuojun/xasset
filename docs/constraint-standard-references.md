# 硬约束数值的规范依据

> 定位：**知识来源文档**。记录 `xasset/tools/constraint/` 里每个硬约束数值的**规范出处**。
> 更新：2026-09
> 关联：`docs/iteration-convergence.md`（硬约束 vs 软规则的边界）、`xasset/tools/constraint/builtin.py`（实现）

---

## 为什么需要这份文档

硬约束里的数值（门宽 0.6m、走廊 0.9m）不能是"我觉得差不多"。它们要么是**国家/行业强制规范**，要么是**人体工学共识**。

**每个数字都要能回答"凭什么"。**

这份文档就是那个"凭什么"的记录。代码里引用常数时，注释指向这里的条目编号。

---

## 使用原则

1. **强制规范优先**——有国标就用国标，没有才用行业标准或人体工学数据
2. **标注到条款**——不能只写"依据住宅设计规范"，要写到第几条
3. **版本要记**——规范会修订，数字可能变，必须记版本年份
4. **区分强制性 vs 推荐性**——GB 是强制，GB/T 是推荐，影响能否作为"非法"判据

## 二、城市 / 乡村 / 山林 / 海洋 / 沙漠

> 这些场景的规范知识远超我的可靠范围，**以下仅为方向提示，具体数值必须查证原始规范后再填**。

| 场景 | 可能的规范来源 | 待查 |
|------|--------------|------|
| 城市 urban | 《城市居住区规划设计标准》GB 50180-2018<br>《城市道路工程设计规范》CJJ 37-2012 | 道路宽度、建筑退线、日照间距、绿地率 |
| 乡村 rural | 《村庄整治技术规范》GB/T 50445<br>各省美丽乡村建设标准 | 村落道路、宅基地尺寸、农田地块 |
| 山林 mountain | 无统一强制规范 | 地形坡度安全限值、林道宽度（多为行业指南） |
| 海洋 ocean | 《海港总体设计规范》JTS 165 等 | 航道宽度、水深要求（强专业领域） |
| 沙漠 desert | 无统一强制规范，多为工程经验 | 沙丘稳定性、防风固沙带宽度 |

> **建议**：这些场景在真正开始做之前，请领域专家提供规范清单，而不是我凭印象列。

## 三、代码引用方式

## 四、规范严格程度验证（基于真实数据）

用 `data/house/converted/rooms/` 的 **99 套真实户型**跑 `understand_hard_constraints()`：

```
总房间数: 99
违反硬约束: 4  (4.0%)
按规则统计:
  region_area_meets_standard       4
```

**结论**：只有 4% 的真实房间不满足国标最小面积，其余全部通过。

这说明规则定得合理：
- **不是形同虚设**——确实能筛出不合规的（4%）
- **不是过严**——96% 的正常户型不会误伤

**注意**：这 4 例正是历史项目数据里真实存在的"小厨房/小卫生间"。它们在国内老房子里很常见，说明**国标是新建住宅的标准，老房改造场景可能需要放宽**。这是产品决策，不是规则错误。

> 后续如果面向旧改场景，建议把 `region_area_meets_standard` 从硬约束降为软规则，或按"新建/改造"模式切换。
