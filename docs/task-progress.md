#### `understand` 视觉路线进度

> **业务约束**：输入几乎总是图片（即使原始是矢量，到手也是栅格图）。因此不追矢量来源，一律按图片处理。
> 图纸/实景由**用户选择**，不自动判定。

| 层 | 职责 | 状态 |
|----|------|------|
| ① 输入类型 | 用户选图纸 / 实景 | ✅ 无需实现（枚举传参） |
| ② 分割 | 图片 → mask | ✅ **阈值+连通域**已接入（`segmenters.py`） |
| **③ 几何后处理** | **mask → 多边形** | ✅ **已实现**（`contour.py`，含坐标系统一） |
| ④ 语义标注 | 多边形 → region_type | 🟡 接口已定，仍是空实现 |
| **Artist 结构** | 想法→落地→校验→回拉 | ✅ 已落地（`max_fix_iterations=1`，回拉已预留） |

**✅ 里程碑（2026-09）：整条链路已跑通真实户型图**

用 Wikipedia 的 `Sample Floorplan.jpg`（842×569）验证：
- 分割出 **7 个区域**
- 轮廓**准确贴合**房间（Eat-in Kitchen / Formal Living / Laundry / 1/2 Bath / Family / Entrance 都能对上）
- 面积有合理梯度（19.0 → 0.66 m²）
- 对比图输出到 `out/compare.png`

**仍在的局限**（已知，有明确路径）：

| 局限 | 原因 | 怎么解 |
|------|------|--------|
| 区域类型全是 `unknown` | `StubLabeler` 未接入 | 接 LLM 或分类器做语义标注 |
| 面积不算准 | 尺度用"最大区域典型面积"反推 | 找参照物（标准门宽 0.9m）反推 |
| 实景照片效果差 | 阈值分割只适合线条图 | 接真实分割模型（SAM 类） |
| 轮廓略外扩 | 分割取"白空间"，墙厚未扣除 | 约束侧做墙厚内缩 |
